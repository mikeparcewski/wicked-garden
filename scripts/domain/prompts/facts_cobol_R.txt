CARD FACTS (COBOL / IBM LE / CICS): CALL 'CEE3ABD' abends the job and does not return. CICS RETURN with TRANSID schedules that transaction for the next input. XCTL transfers control and does not return. HOW A RUN STARTS: a batch program starts at the first paragraph of its PROCEDURE DIVISION, with each WORKING-STORAGE item holding its VALUE clause; a file's record area holds the last record read, and still holds it after the read that reaches end of file. A CICS program starts at the first paragraph of its PROCEDURE DIVISION on EVERY task (each screen interaction is a new task), with fresh WORKING-STORAGE: each item holds its VALUE clause, and an item with no VALUE clause holds no value that any line of the program set in an earlier task. Values carry from one task to the next only through the COMMAREA, which the program receives as DFHCOMMAREA with length EIBCALEN (EIBCALEN = 0 means none was passed, so nothing from an earlier task is present); a MOVE of DFHCOMMAREA to a group restores every item inside that group. INITIALIZE sets alphanumeric items to spaces and numeric items to zero.
